# 08-03 — Реконсиляция и сглаживание

**Неделя:** 8 — Качество netcode
**Зависит от:** 08-02
**Блокирует:** 08-05
**Оценка:** ~120 строк нового кода

## Контекст

Предсказание (08-02) неизбежно расходится с сервером: столкновение с другим
игроком, урон от врага, отброшенный сервером ввод. Без коррекции клиент
уплывёт в свою реальность.

Реконсиляция: получив снапшот с `last_input_tick`, клиент ставит своего
игрока в серверную позицию и **переигрывает** все вводы новее этого тика.

## Что сделать

- [ ] По приходу снапшота:
  1. взять `snap.players[local]` → позиция/хп локального игрока
  2. выбросить из `InputHistory` всё с `tick <= snap.last_input_tick`
  3. для каждого оставшегося ввода — `world_step()` с одним игроком
  4. результат — новая предсказанная позиция
- [ ] Сглаживание: если расхождение между старой предсказанной позицией и
      новой меньше порога — не телепортировать, а «дотягивать» за несколько
      кадров:
  ```c
  #define RECONCILE_SNAP_DIST   0.5f   /* больше — телепорт */
  #define RECONCILE_SMOOTH_RATE 10.0f  /* доля/с, экспоненциальное сближение */
  ```
      Ошибка хранится как визуальное смещение и затухает; симуляционная
      позиция при этом сразу корректная
- [ ] Угол не реконсилируется: его считает клиент (06-06), сервер принимает
- [ ] Защита от переигрывания огромной истории: если неподтверждённых вводов
      больше `INPUT_HISTORY`, значит связь провалилась — полный сброс на
      серверное состояние
- [ ] Счётчик расхождений и их средняя величина — для оверлея (08-04)

## Затрагиваемые файлы

`net_client.c/.h`, `world.c`

## Критерий готовности

- [ ] При стабильных 150 мс задержки расхождение стремится к нулю,
      камера не дёргается
- [ ] Столкновение с другим игроком корректируется плавно, без телепорта
- [ ] Урон от врага применяется без отката позиции
- [ ] Полная потеря связи на 2 с и восстановление → игрок оказывается в
      серверной позиции без застреваний в стенах
- [ ] Тест воспроизводимости из 06-01 всё ещё проходит

## Замечания

Переигрывание 10–20 тиков каждый снапшот — копейки по производительности:
`world_step()` для одного игрока без ИИ стоит микросекунды, а число
остальных игроков на это не влияет (переигрывается только свой).

Порог `RECONCILE_SNAP_DIST` подбирается опытно. Слишком маленький — камера
дёргается на каждом снапшоте; слишком большой — читерский клиент сможет
уползать. Для LAN-демо 0.5 клетки разумно.

Частая ошибка: переигрывать вводы **вместе с** ИИ и другими игроками. Это
дорого и бессмысленно — их состояние всё равно приедет в следующем снапшоте.
Переигрывается только движение своего игрока по статичной геометрии.

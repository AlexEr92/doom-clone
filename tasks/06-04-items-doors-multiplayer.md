# 06-04 — Предметы и двери на N игроков

**Неделя:** 6 — Мультиплеерная логика локально
**Зависит от:** 06-02
**Блокирует:** —
**Оценка:** ~60 строк изменений

## Контекст

Две связанные проблемы:

1. `item_update()` (`item.c:55-71`) проверяет подбор только одним игроком.
2. Позиция предмета живёт **в спрайте**: `item_add()` (`item.c:19-20`)
   оставляет `it->x/y` нулями, а `item_update()` (`item.c:62-65`) читает
   `sp->x`, `sp->y`. Поскольку на неделе 6 спрайты становятся клиентской
   сущностью (задача 06-05), симуляция потеряет источник координат.

`door_try_use()` (`door.c:46`) тоже завязан на одного игрока.

## Что сделать

- [ ] `item_add()` — принимать и сохранять `x, y`; убрать зависимость от
      `sprite_id` в логике (поле можно удалить целиком)
- [ ] `item_update()`:
  ```c
  void item_update(ItemList *il, PlayerState *players, int count, EventQueue *ev);
  ```
      цикл по предметам × игрокам; предмет достаётся первому подошедшему
      по возрастанию `id` (детерминизм при одновременном подборе)
- [ ] `apply_pickup()` (`item.c:24-53`) — на `PlayerState`, оружие берётся
      из игрока (после 05-02); вместо `audio_play_volume()` — событие
      `EV_PICKUP` с координатами предмета
- [ ] `door_try_use(DoorList *dl, const PlayerState *p, const Map *m,
      EventQueue *ev)` — вызывается в цикле по игрокам, у которых нажат `use`
- [ ] Дверь, открытая одним игроком, открыта для всех (уже так — состояние
      в `DoorList`, менять не надо); проверить, что таймер автозакрытия
      (`door.c:96-101`) не закрывает дверь в проходящем игроке

## Затрагиваемые файлы

`item.h/.c`, `door.h/.c`, `world.c`

## Критерий готовности

- [ ] `grep -n "sprite" src/item.c` — пусто
- [ ] Два игрока подходят к аптечке одновременно → подбирает ровно один
- [ ] Дверь, открытая игроком 0, проходима для игрока 1
- [ ] Одиночная игра: все предметы подбираются как раньше

## Замечания

Про автозакрытие двери: сейчас `DOOR_OPEN_TIME 4.0` и закрытие не проверяет,
стоит ли кто-то в проёме — дверь закроется прямо в игроке, и он окажется
внутри стены (`map_is_wall_door()` начнёт возвращать 1 в его клетке).
С одним игроком это редкость, с четырьмя — регулярный баг. Стоит добавить
в `door_update_all()` проверку: не закрываться, если в клетке двери есть
живой игрок.

# 08-02 — Предсказание своего игрока

**Неделя:** 8 — Качество netcode
**Зависит от:** 07-05, 06-01, 06-06
**Блокирует:** 08-03
**Оценка:** ~150 строк нового кода

## Контекст

Сейчас клиент ждёт подтверждения сервера, чтобы сдвинуть своего игрока —
на RTT 50 мс это ощущается как «залипание» управления, на 150 мс играть
невозможно.

Решение: клиент применяет свой ввод локально сразу, тем же `world_step()`
(06-01), и запоминает неподтверждённые вводы. Сходимость с сервером —
задача 08-03.

## Что сделать

- [ ] Кольцевой буфер вводов:
  ```c
  #define INPUT_HISTORY 128   /* ~2 с при 60 Гц */
  typedef struct {
      PlayerInput inputs[INPUT_HISTORY];
      int head, count;
  } InputHistory;
  ```
- [ ] Каждый тик: отправить `MSG_INPUT`, положить в историю и **сразу**
      применить локально через `world_step()` по локальному `World`
- [ ] Локального игрока исключить из `snapshot_apply()` — иначе снапшот
      будет затирать предсказанную позицию и вернётся дёрганье
- [ ] Изолировать предсказание от чужих сущностей: предсказывается **только**
      движение своего игрока и его коллизии с картой. Врагов, двери и
      чужих игроков предсказывать не пытаемся — берём из снапшота
- [ ] Стрельба не предсказывается: локально проигрывается только анимация
      отдачи и звук, урон приходит от сервера. Иначе будут «фантомные»
      попадания
- [ ] Расход патронов предсказывать можно (мгновенная обратная связь в HUD),
      но при расхождении — сервер прав

## Затрагиваемые файлы

`net_client.c/.h`, `world.c`, `main.c`

## Критерий готовности

- [ ] Управление отзывчиво при искусственных 150 мс задержки
- [ ] Стена останавливает игрока мгновенно, без «продавливания» и отката
- [ ] Локальная позиция при RTT ≈ 0 совпадает с серверной с точностью
      до float-погрешности (это база для 08-03)
- [ ] Отладочный вывод расхождения предсказания (полноценный оверлей — 08-04)

## Замечания

Ключевое условие корректности: клиент и сервер обязаны выполнять **ровно
ту же** функцию `world_step()`. Любая ветка вида «на клиенте пропустим ИИ»
внутри неё создаёт расхождение, которое проявится не сразу и будет искаться
долго. Разделение делается снаружи — тем, какие части результата клиент
оставляет себе.

`rand()` — источник расхождения по определению. Именно поэтому стрельба
(с разбросом дробовика, `weapon.c:84`) не предсказывается.

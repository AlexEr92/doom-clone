**Откуда:** замечено при выполнении chore-014
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~15–25 строк в `coverage.sh`, правка нескольких фраз в `SKILL.md`; `check.sh` по чтению менять не нужно. Оценка по чтению `run_tests()` и `summary()`; объём чистки каталога зависит от выбранного способа.
**Приоритет:** гейт ломается ровно в сценарии, от которого защищает (тест удалён или переименован), и при этом врёт о причине.

## Контекст

`.claude/skills/coverage/coverage.sh` собирает `build-cov/`, удаляет `*.gcda`, гоняет `ctest` и считает покрытие через `gcovr`. Статус выхода по шапке скрипта и `SKILL.md`: 0 — пороги выдержаны, 1 — не выдержаны, 2 — сбой сборки, тестов или инструментов.

### Что происходит

Два дефекта, второй скрывает первый.

**(а) Устаревшие `.gcno`.** `run_tests()` удаляет только `*.gcda`. Когда тестовый файл удалён из `tests/` и его `doom_test(...)` убран из `tests/CMakeLists.txt`, cmake перестраивает проект, но каталог объектов исчезнувшей цели остаётся: `build-cov/tests/CMakeFiles/test_map.dir/test_map.c.gcno` лежит без `.gcda` и без исходника. `gcovr` вызывает на нём `gcov`, тот пишет `Cannot open source file …/tests/test_map.c`, затем `Could not open output file 'event.h##<hash>.gcov' (gcovr could not infer a working directory that resolved it.)`, и `gcovr` завершается с ошибкой без сводки. Вероятно, то же происходит после переименования тестового файла.

**(б) Ошибка инструмента как «НИЖЕ ПОРОГА».** `summary()` проверяет только `rc -ne 0` от `gcovr` и в этом случае печатает `покрытие: НИЖЕ ПОРОГА (строки 78 %, decisions 68 %)` и возвращает 1, хотя числа не посчитаны. `gcovr` 7.0 (`gcovr/__main__.py`) возвращает битовую маску: 0 успех, 1 ошибка командной строки, 2 строки ниже порога, 4 ветки, 8 decisions, 16 функции, 64 ошибка чтения, 128 ошибка записи. Пороги задаются только `--fail-under-line` и `--fail-under-decision`, значит о недоборе говорят коды 2, 8 и 10; всё остальное — сбой инструмента.

`check.sh` разбирает код `coverage.sh changed` в блоке `# --- coverage ---`: 0 → «пороги выдержаны», 1 → «НИЖЕ ПОРОГА», остальное → «не посчитано». Разбор верен, пока сам `coverage.sh` отдаёт 2 при сбое; сейчас он отдаёт 1, и `check.sh` повторяет ложное «НИЖЕ ПОРОГА».

### Как воспроизвести

Проверено на копии дерева (gcovr 7.0, gcc 13.3), не на рабочем:

1. `coverage.sh` — `build-cov/` собран со всеми тестами.
2. Удалить `tests/test_map.c`, закомментировать `doom_test(map …)` в `tests/CMakeLists.txt`.
3. `coverage.sh` ещё раз: ошибка gcov из описания выше, `gcovr` падает.
4. Вывод `покрытие: НИЖЕ ПОРОГА (строки 78 %, decisions 68 %)`, код 1.

## Что сделать

- [ ] (а) Сделать так, чтобы `.gcno` и объекты целей, которых в сборке больше нет, не попадали в замер. Способ на выбор исполнителя: удалять перед `ctest` все `.gcno`, у которых нет исходника; чистить `build-cov/tests/CMakeFiles/*.dir` без соответствующей цели; либо пересобирать с очисткой. Выбор обосновать в «Замечаниях» к закрытию, учитывая время прогона `check.sh` (~15 с в целом).
- [ ] (б) В `summary()` различать коды `gcovr`: 0 — пороги выдержаны; 2, 8 и 10 — «НИЖЕ ПОРОГА», код 1; любой другой — сообщение о сбое инструмента с кодом `gcovr` и выход с 2. Вывод `gcovr` при сбое не прятать.
- [ ] В `changed_lines()` вызов `gcovr --json … 2>/dev/null || exit 2` оставить с кодом 2, но показать причину сбоя (сейчас stderr выброшен).
- [ ] Обновить `SKILL.md` покрытия, если он описывает коды выхода или поведение при удалённых тестах; шапку `coverage.sh` сверить.
- [ ] Сверить `check.sh`: на коде 2 от `coverage.sh` он печатает «не посчитано» и добавляет покрытие в `failed`. Правок не требуется, если так и есть; в противном случае поправить.

## Критерий готовности

- [ ] При уже собранном `build-cov/` удалить тестовый файл вместе с его `doom_test(...)` (на копии дерева): `coverage.sh` печатает реальные числа и `пороги выдержаны` либо `НИЖЕ ПОРОГА` по ним, в выводе нет `Cannot open source file` и `Could not open output file`.
- [ ] То же после переименования тестового файла вместе с регистрацией.
- [ ] Принудительный сбой `gcovr` (нечитаемый `.gcno` или заведомо неверный аргумент) даёт код выхода 2 и сообщение о сбое инструмента, не `НИЖЕ ПОРОГА`.
- [ ] Реальный недобор (временно поднять `LINE_MIN` выше измеренного) по-прежнему даёт код 1 и `НИЖЕ ПОРОГА`.
- [ ] `check.sh` на сбое `gcovr` печатает `покрытие: не посчитано`, на недоборе — `НИЖЕ ПОРОГА`, на штатном прогоне — `пороги выдержаны`.
- [ ] `check.sh` проходит на чистом дереве.

## Замечания

- Дефект (а) связан с тем, что `ctest` и `gcovr` смотрят на разные множества целей. Простое `rm -rf build-cov` лечит, но стоит полной пересборки, поэтому как единственный способ нежелательно.

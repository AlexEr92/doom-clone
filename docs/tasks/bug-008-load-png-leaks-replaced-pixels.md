# bug-008 — `assets_load_png()` теряет пиксели слота, который замещает

**Откуда:** замечено при подключении файловых текстур в
`10-01-sprite-sheet-loader.md`
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~5 строк изменений, только `assets.c`

## Что происходит

Комментарий в заголовке обещает замену на месте:

```c
/* Load PNG from path into tex (replaces existing). Returns 0 on success. */
int assets_load_png(Texture *tex, const char *path);   /* assets.h */
```

Реализация (`assets.c`) присваивает `tex->pixels = px`, не освободив то, что
там лежало. Слоты `Assets` к моменту загрузки уже заполнены генераторами, то
есть «замена существующего» — ровно тот случай, ради которого функция и
написана, и ровно тот, в котором она теряет буфер.

Сегодня это не течёт: единственный вызывающий — `assets_load_sheet()`, и он
передаёт обнулённую локальную `Texture`, а слот меняет через
`texture_free()` + присваивание. То есть дефект целиком в контракте: любой
следующий вызывающий, поверивший комментарию, получит утечку размером с
текстуру.

## Что сделать

- [ ] Либо освобождать прежние пиксели в начале `assets_load_png()` через
      `texture_free()` — тогда комментарий становится правдой, а вызов с
      неинициализированной `Texture` начинает требовать обнуления, что уже
      и так делают все вызывающие
- [ ] Либо переписать комментарий: функция заполняет `Texture`, владельцем
      прежнего буфера остаётся вызывающий

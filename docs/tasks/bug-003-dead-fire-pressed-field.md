# bug-003 — Мёртвое поле `fire_pressed`

**Откуда:** замечено при разборе обработки ввода для скилла запуска

**Блокирует:** —
**Оценка:** ~10 строк изменений

## Что происходит

`InputState.fire_pressed` (`input.h`) объявлено как фронт нажатия и
добросовестно поддерживается в `input.c` — выставляется по `SDL_KEYDOWN`
и по нажатию левой кнопки мыши, сбрасывается в `input_end_frame()` — но
**не читается нигде**:

```
src/input.h:10:    int fire_pressed;     /* edge: set on keydown, cleared by consumer */
src/input.c:31:                    in->fire_pressed = 1;
src/input.c:62:                    in->fire_pressed = 1;
src/input.c:78:    in->fire_pressed = 0;
```

Стрельба в `main.c` смотрит на удерживаемое `input.fire`, а не на фронт.
Комментарий «cleared by consumer» описывает потребителя, которого нет.

Само по себе это не баг поведения: стрельба работает, а темп ограничен
кулдауном оружия. Проблема в том, что поле выглядит рабочим и приглашает
на него опереться.

## Что сделать

Выбрать одно из двух и довести до конца.

**Вариант А — удалить.** Убрать поле и три присваивания. Проще всего,
поведение не меняется.

**Вариант Б — использовать.** Если полуавтоматический огонь по одному
выстрелу на нажатие когда-нибудь понадобится, поле пригодится — но тогда
надо и читать его, и починить сброс: сейчас `input_end_frame()` вызывается
внутри фикс-шага (`main.c`), так что фронт гаснет после первого под-шага
и при низком FPS теряется целиком.

Рекомендуется **А**: задача 06-06 всё равно перестраивает ввод на
`PlayerInput` с битовой маской и своим механизмом фронтов, так что
нынешнее поле в любом случае не доживёт.

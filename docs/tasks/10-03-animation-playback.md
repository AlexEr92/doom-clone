# 10-03 — Проигрывание анимаций на клиенте

**Этап:** 10 — Графика и арсенал
**Зависит от:** 10-01, 06-05
**Блокирует:** 10-04, 10-08
**Оценка:** ~200 строк изменений

## Контекст

После 10-01 текстура умеет хранить несколько кадров, но выбирает кадр
никто: `sprite_render()` рисует нулевой, `hud_draw_weapon()` — тоже.
Анимация оружия существует ровно в виде отдачи: `Weapon.anim`
(`weapon.h:24`) убывает от 1 до 0, и `hud_draw_weapon()` (`hud.c:82`)
сдвигает картинку вниз на `18 * anim` пикселей.

Состояние, из которого выводится анимация, уже всё есть: скорость игрока,
`Weapon.anim`, здоровье, факт недавнего урона. Не хватает связи «состояние
сущности → номер кадра» и часов, которые эту анимацию прокручивают.

Важная деталь про часы: после 06-05 `SpriteList` пересобирается каждый
кадр из состояния мира, поэтому фаза анимации в `Sprite` жить не может —
она обнулялась бы каждый кадр. Фаза принадлежит клиенту и хранится по
идентификатору сущности.

Анимация целиком клиентская и в `world_step()` не входит: она не влияет
ни на попадания, ни на сохранение детерминизма (`tests/replay_test.c`).

## Что сделать

- [ ] Перечисление анимаций рядом с клиентскими спрайтами:
      ```c
      typedef enum { ANIM_IDLE = 0, ANIM_RUN, ANIM_SHOOT, ANIM_PAIN, ANIM_DEATH, ANIM_COUNT } AnimId;
      ```
- [ ] `Assets` получает таблицу листов персонажа вместо трёх отдельных
      полей врага: `Texture player_anim[ANIM_COUNT]` (в 10-04 она станет
      двумерной по скинам). `sprite_texture()` (`sprite.c:48-59`) выбирает
      лист по анимации, а не по типу спрайта
- [ ] `Sprite` получает поля `anim` и `frame`; их заполняет
      `sprites_build_from_world()` из 06-05
- [ ] Часы анимации на клиенте: массив по идентификатору игрока и врага,
      в нём текущая анимация и фаза. Переход на другую анимацию сбрасывает
      фазу; `ANIM_DEATH` не зациклена и залипает на последнем кадре —
      он же и есть труп, отдельный `SPRITE_ENEMY_DEAD` больше не нужен
- [ ] Правила выбора анимации: здоровье кончилось — `ANIM_DEATH`; недавно
      получен урон — `ANIM_PAIN` на фиксированное время; `Weapon.anim > 0`
      — `ANIM_SHOOT`; скорость выше порога — `ANIM_RUN`; иначе `ANIM_IDLE`
- [ ] Кадр оружия в HUD — из `Weapon.anim`: при `anim == 0` кадр 0,
      иначе `anim` раскладывается по кадрам с первого по последний.
      Отдача (`hud.c:82`) остаётся
- [ ] Скорости анимаций — константами в клиентском коде, не в файлах:
      частота кадров бега и смерти, длительность гримасы боли. Тайминг
      выстрела задаёт `Weapon.fire_cd`, дублировать его константой нельзя

## Затрагиваемые файлы

`src/sprite.h`, `src/sprite.c`, `src/assets.h`, `src/assets.c`,

## Критерий готовности

- [ ] Без файловой графики игра выглядит как сегодня: у процедурных
      текстур один кадр, и любая анимация показывает его
- [ ] С тестовыми листами: бегущий персонаж перебирает кадры, стоящий —
      нет; смерть проигрывается один раз и остаётся лежать последним
      кадром; повторный урон по трупу анимацию не перезапускает
- [ ] Выстрел из пистолета показывает кадры выстрела ровно на время
      `fire_cd`, без залипания и без пропуска кадров при 60 FPS
- [ ] Девять чужих игроков анимируются независимо друг от друга
- [ ] `driver.sh smoke` проходит, `ctest` зелёный

## Замечания

Фаза анимации по идентификатору, а не по спрайту, заодно решает проблему
исчезновения из кадра: игрок, вышедший из поля зрения и вернувшийся,
продолжает свою анимацию, а не начинает её заново.

Смерть по сети приходит как смена состояния, а не как событие, поэтому
клиент, подключившийся к матчу позже, увидит уже лежащий труп на
последнем кадре — это правильное поведение, а не пропуск анимации.

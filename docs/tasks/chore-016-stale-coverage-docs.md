## Контекст

Описания в двух `SKILL.md` разошлись с тем, что печатают скрипты. Замер на
текущем дереве (`coverage.sh report`: строки 81.6 %, decisions 71.4 %;
`check.sh`: `ctest: 19/19`).

**`.claude/skills/coverage/SKILL.md`, раздел «Reading the numbers»:**

- Пункт «Only modules linked into some test are in the denominator»
  называет вне знаменателя `engine.c`, `hud.c`, `main.c`, `raycast.c`,
  `sprite.c`, `utils.c`. В `tests/CMakeLists.txt` `hud.c` линкуется в
  `doom_test(hud …)` (в отчёте 3 %, 5 из 156 строк), `sprite.c` — в
  `doom_test(sprite …)` (55 %). Без данных остаются `engine.c`, `main.c`,
  `raycast.c` и `utils.c`: `doom_test(utils)` объявлен без `SRC`, тест
  берёт только `utils.h` (он в отчёте, 100 %), а `src/utils.c` ни в один
  тест не линкуется.
- Пункт «`assets.c` (20 %) and `game.c` (32 %) are not badly tested»:
  сейчас `assets.c` 92 %, `game.c` 32 %. Низкого числа у `hud.c` (3 %)
  пункт не объясняет: нужно сказать, что из `hud.c` проверяет тест, а что
  — отрисовка, которую без фреймбуфера не запустить.
- Хвост примера `changed` («против HEAD~8») показывает строку
  `src/sprite.c: не линкуется ни в один тест — не измеряется`; для
  `sprite.c` это больше неправда. Строка «не линкуется» относится к
  модулю, который действительно не линкуется (`raycast.c`, `engine.c`).

**`.claude/skills/check/SKILL.md`, «Verified output on a clean tree»:**
`ctest: 12/12` (сейчас 19/19), `покрытие: строки 68.1%, decisions 56.3%`
(сейчас 81.6 % и 71.4 %), `smoke: ок (6 PASS)`. На чистом дереве
`check.sh` печатает `smoke: не нужен — изменения не доходят до src/,
assets/, CMakeLists.txt`, так что пример собран вручную, а не снят с
прогона.

Пороги покрытия и пример итоговой сводки `coverage.sh` в
`.claude/skills/coverage/SKILL.md` соответствуют замеру; эта задача их не
трогает.

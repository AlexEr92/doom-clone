# 07-06 — Звук через сетевые события

**Этап:** 7 — Сеть: транспорт, протокол, снапшоты
**Зависит от:** 07-05
**Блокирует:** —
**Оценка:** ~60 строк изменений

## Контекст

В 05-05 прямые вызовы `audio_play()` из логики заменены на запись в
`EventQueue`. В 07-03 события попали в снапшот как `NetEvent`. Осталось
замкнуть цепочку: клиент проигрывает события с дистанцией, посчитанной
от **своего** игрока.

Существующий API `audio.h:31` (`audio_play(a, id, dist, maxdist)`) менять
не нужно — он изначально принимает готовую дистанцию.

## Что сделать

- [ ] `void audio_play_events(Audio *a, const EventQueue *q,
      const PlayerState *listener);`
      — маппинг `GameEventKind` → `SoundId` и вызов `audio_play()` с
      `dist = hypot(ev.x - listener->x, ev.y - listener->y)`
- [ ] Вызывать раз в кадр после `client_poll()` / `server_tick()`
- [ ] События, привязанные к слушателю, а не к точке:
  - `EV_NO_AMMO`, `EV_PICKUP` своего игрока → `audio_play_volume()`
    на полной громкости (используется `actor` в `NetEvent`)
  - `EV_PLAYER_HURT` чужого игрока → пространственный звук;
    своего → полная громкость
- [ ] Анимация отдачи оружия (`Weapon.anim`) у **чужих** игроков не нужна,
      но `EV_SHOT` от чужого должен быть слышен позиционно
- [ ] Ограничить одновременное воспроизведение: при 10 игроках залпы дают
      постоянный всплеск событий; SDL_mixer по умолчанию 8 каналов
      (`Mix_AllocateChannels`) — поднять до 32 и дедуплицировать одинаковые
      события в одном тике
- [ ] **Отбор событий по дистанции на сервере:** `MAX_EVENTS 32` на снапшот
      при 10 игроках переполняется. Сервер формирует список событий
      персонально для каждого клиента: сначала события его игрока, затем
      остальные по возрастанию дистанции, лишние отбрасываются.
      Событие дальше `maxdist` самого громкого звука слать бессмысленно —
      клиент его всё равно не услышит

## Затрагиваемые файлы

`audio.h/.c`, `net_client.c`, `main.c`

## Критерий готовности

- [ ] Выстрел чужого игрока слышен тише по мере удаления и глохнет
      за `maxdist`
- [ ] Свой выстрел, подбор и «нет патронов» звучат на полной громкости
- [ ] Смерть врага слышна обоим игрокам
- [ ] Залп из 7 дробин даёт один звук выстрела, а не семь
- [ ] 10 игроков, стреляющих одновременно, не переполняют очередь событий
      и не съедают все каналы SDL_mixer

## Замечания

`MAX_EVENTS 32` на снапшот — при потере пакета часть звуков пропадёт.
Для звука это приемлемо (в отличие от состояния мира, которое приезжает
целиком в каждом снапшоте). Делать события надёжными не стоит: опоздавший
на 300 мс звук выстрела хуже, чем его отсутствие.

Отбор по дистанции — не только экономия трафика: в deathmatch на 10 человек
слышимость выстрелов работает как разведка, и слышать надо именно ближних,
а не первых попавших в буфер.

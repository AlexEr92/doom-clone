# bug-006 — `draw_int()` рисует цифры HUD в обратном порядке

**Откуда:** замечено при разборе `hud.c`
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~5 строк изменений

## Что происходит

`draw_int()` (`src/hud.c:46-67`) рисует любое число из двух и более цифр
зеркально. Функция вызывается в трёх местах: HP (`hud.c:203`), броня
(`hud.c:219`) и патроны (`hud.c:241`) — все три показывают перевёрнутое
число.

```c
int tmp = value;
while (tmp > 0) {
    buf[n++] = (char)('0' + tmp % 10);   /* младший разряд в buf[0] */
    tmp /= 10;
}
int x = x0 + (n - 1) * 4 * scale;
for (int i = n - 1; i >= 0; i--) {
    draw_glyph(fb, x, y0, buf[i] - '0', color, scale);
    x -= 4 * scale;
}
```

`buf` заполняется от младшего разряда к старшему (`buf[0]` — младший).
Цикл идёт по `buf` от конца к началу, то есть от старшего разряда к
младшему — но координата `x` при этом тоже уменьшается на каждом шаге.
В результате старший разряд рисуется в самой правой позиции, а младший —
в самой левой, то есть слева направо на экране получается перевёрнутое
число.

Разбор на `value = 47`: `buf[0]='7'`, `buf[1]='4'`, `n = 2`, `x` стартует
с `x0 + 4`. Итерация `i = 1` рисует `'4'` в `x0 + 4` (правая позиция),
итерация `i = 0` рисует `'7'` в `x0` (левая позиция). Слева направо
получается `74` вместо `47`.

## Как воспроизвести

Снято под Xvfb через `driver.sh`, сверено с телеметрией в заголовке окна
(заголовок выводит те же значения обычным `snprintf`, поэтому ему можно
доверять):

- заголовок `HP 100` — HUD рисует `001`
- заголовок `ammo 47/50` — HUD рисует `74`
- заголовок `ammo 50/50` — HUD рисует `05`

Однозначные значения (броня `0`, патроны `7`) на скриншоте выглядят
правильно — с одной цифрой порядок рисования не имеет значения, поэтому
дефект легко не заметить: он проявляется только на двух и более разрядах.

## Что сделать

- [ ] Исправить порядок рисования в `draw_int()` так, чтобы старший
      разряд оказывался слева, при этом самый левый глиф должен
      по-прежнему стоять в `x0` — эта координата привязана к полоскам
      HP/брони/патронов, её менять не нужно
- [ ] Не трогать подсчёт и отрисовку самих полосок (`hpw`, `arw`, `amw`
      в `hud_draw()`) — они не зависят от `draw_int()` и уже верны

## Критерий готовности

- [ ] `draw_int()` рисует старший разряд слева, младший справа
- [ ] На скриншоте `driver.sh` число в HUD совпадает с телеметрией в
      заголовке окна: HP `100` отображается как `100`, патроны `47` —
      как `47`, `50` — как `50`
- [ ] Однозначные значения и `0` отображаются как прежде (регрессии нет)
- [ ] Число не сдвинулось относительно полосок HP/брони/патронов
- [ ] `driver.sh smoke` проходит

## Замечания

Ветка `if (value < 0) { value = -value; }` в начале `draw_int()` мёртвая:
отрицательных значений не бывает — `enemy_update_all()` (`enemy.c:197-199`)
обрезает `hp` по нулю, `item.c:35,42` держит `hp`/`armor` в `[0, 100]`.
Трогать её в рамках этого багфикса не обязательно, но если исполнитель
захочет убрать заодно — не будет лишним.

Проверка делается скриншотом запущенной игры, а не тестом — рендер HUD
тестами не покрыт (`docs/requirements.md` §9 и `test-001` — про
`world_step()` и то, что уже тестируемо без фреймбуфера; отрисовка цифр
в их объём не входит).

Второй экземпляр шрифта живёт в `src/game.c` (`glyph_digits`,
`draw_text()`) — он рисует строку слева направо и этой ошибки не
содержит. Объединение двух шрифтов в один модуль — отдельная тема, не
предмет этой задачи.

# 06-02 — Массив `players[MAX_PLAYERS]`

**Этап:** 6 — Мультиплеерная логика локально
**Зависит от:** 06-01
**Блокирует:** 06-03, 06-04, 06-05, 07-03, 09-01
**Оценка:** ~80 строк изменений

## Контекст

`World` содержит ровно один `Player`. Все системы (`enemy.c`, `item.c`,
`door.c`, `hud.c`) написаны под единственного игрока.

## Что сделать

- [ ] В `world.h`:
  ```c
  #define MAX_PLAYERS 10

  typedef struct {
      /* ... */
      PlayerState players[MAX_PLAYERS];
      int         player_count;
      int         local_player;   /* индекс своего игрока; -1 на сервере */
  } World;
  ```
- [ ] Поднять `MAX_SPRITES` с 96 до 192 (`sprite.h:27`): 32 врага +
      64 предмета + бочки + 9 чужих игроков ≈ 110 переполняют текущий лимит
- [ ] `world_add_player(World *w, int spawn_index) -> int id`
      и `world_remove_player(World *w, int id)`
      (при отключении игрок помечается неактивным, слот переиспользуется)
- [ ] `world_step()` — цикл по игрокам: движение и стрельба каждого по
      своему элементу `inputs[]`, сопоставление по `PlayerState.id`
- [ ] Рендер и HUD берут `w->players[w->local_player]`
- [ ] Коллизии игрок↔игрок: игроки друг сквозь друга **не проходят** —
      добавить в `try_move()` (`player.c:22-30`) проверку дистанции до
      остальных живых игроков (`2 * PLAYER_RADIUS`)

## Затрагиваемые файлы

`world.h/.c`, `player.c/.h`, `main.c`, `hud.c`

## Критерий готовности

- [ ] `world_add_player()` десять раз → 10 игроков в мире, все обновляются
- [ ] Второй игрок (пока без управления, стоит на месте) виден как
      препятствие: об него нельзя пройти
- [ ] 10 игроков не переполняют `SpriteList` (проверить `sprite_add()`
      на возврат -1)
- [ ] Игра с одним игроком не изменилась

## Замечания

`local_player = -1` на выделенном сервере — все места, читающие
`players[local_player]`, обязаны это учитывать. Проще всего: рендер, HUD и
аудио вообще не вызываются при `local_player < 0`.

Коллизию игрок↔игрок легко сделать источником рассинхрона предсказания:
порядок обхода игроков в `world_step()` влияет на результат. Порядок —
всегда по возрастанию `id`, и на сервере, и на клиенте.

Коллизии игрок↔игрок — O(N²) = 100 проверок на тик при 10 игроках. Это
незначительно, оптимизировать не нужно; пространственные структуры для
карты 48×48 избыточны.

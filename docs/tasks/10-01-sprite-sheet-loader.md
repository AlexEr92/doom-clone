# 10-01 — Формат листа кадров и загрузчик файловых текстур

**Этап:** 10 — Графика и арсенал
**Зависит от:** —
**Блокирует:** 10-03, 10-04, 10-05, 10-08
**Оценка:** ~250 строк изменений

## Контекст

`Texture` (`assets.h:9-12`) — это одна картинка целиком, и весь рендер
исходит из того, что кадр ровно один: `sprite_render()` (`sprite.c:122-186`)
берёт `tex->w`/`tex->h` как размер спрайта, `hud_draw_weapon()`
(`hud.c:69-113`) — как размер оружия. Анимации нет ни у чего.

Загрузчик PNG написан и не вызывается ни разу:

```c
int assets_load_png(Texture *tex, const char *path);   /* assets.h:33 */
```

Реализация (`assets.c:338-362`) читает файл через `stbi_load()`
(`vendor/stb_image.h`, собран с `STBI_ONLY_PNG`) и упаковывает пиксели в
том же порядке байт, что и `make_color()` (`utils.h:48-51`), — с форматом
текстуры `SDL_PIXELFORMAT_ABGR8888` он уже согласован, пересчитывать
ничего не нужно.

Файловая графика приходит листами кадров, а не отдельными картинками
(`docs/assets-spec.md`), и приходит она из генеративной модели: с
непрозрачным фоном и сглаженными краями. Рендер полутонов не
знает — и `sprite_render()` (`sprite.c:180-182`), и `hud_draw_weapon()`
(`hud.c:106-109`) пропускают пиксель только при альфе строго 0, а любой
другой альфа-байт рисуют непрозрачным. Значит приведение к бинарной
прозрачности — работа загрузчика, а не художника.

## Что сделать

- [ ] Расширить `Texture` (`assets.h:9-12`) полями кадра:
      ```c
      typedef struct {
          int w, h;         /* whole image */
          int fw, fh;       /* one frame */
          int cols, rows;   /* w / fw, h / fh */
          uint32_t *pixels;
      } Texture;
      ```
      Односкадровая текстура — это `fw == w`, `fh == h`, `cols == rows == 1`.
      Переименовывать тип в `SpriteSheet` не нужно: стены, пол и потолок
      остаются одним кадром, и переименование даст только шум в диффе
- [ ] Завести общий `texture_alloc(Texture *t, int w, int h)` и перевести
      на него все `gen_*()` (`assets.c:41-336`), чтобы поля кадра
      заполнялись в одном месте, а не тринадцати
- [ ] Адресация кадра — inline-хелпер в `assets.h`, шаг строки остаётся
      равным `t->w`:
      ```c
      static inline const uint32_t *texture_frame(const Texture *t, int col, int row);
      ```
- [ ] Новый загрузчик поверх `assets_load_png()`:
      ```c
      int assets_load_sheet(Texture *t, const char *path, int fw, int fh);
      ```
      Он: сверяет суффикс `_<fw>x<fh>` в имени файла с аргументами;
      проверяет `w % fw == 0 && h % fh == 0`; выбивает `#FF00FF` в
      `alpha = 0`; приводит остальную альфу к `a < 128 ? 0 : 255`;
      заполняет `cols`/`rows`. Любое несовпадение — сообщение в `stderr`
      и возврат ошибки, слот не трогается
- [ ] Разбор суффикса вынести в отдельную функцию, чтобы её можно было
      покрыть тестом:
      ```c
      int assets_parse_frame_size(const char *path, int *fw, int *fh);
      ```
- [ ] Таблица слотов в `assets.c`: путь без расширения, ожидаемый размер
      кадра, указатель на поле `Assets`. `assets_init()` проходит её после
      генераторов. Отсутствие файла — штатное состояние: слот остаётся
      процедурным, в `stderr` ничего не пишется (проверка `fopen` до
      вызова загрузчика). Битый или несогласованный файл — предупреждение
- [ ] `gen_missing()` — шашечка магента/чёрный 64×64, один кадр. Она нужна
      не здесь, а в 10-04 и 10-05, где процедурного варианта у сущности
      нет вовсе и «молча оставить как было» нечего
- [ ] Провести номер кадра через рендер: `sprite_render()` берёт кадр из
      `Sprite` (поле добавляет 10-03, пока считать нулём), `hud_draw_weapon()`
      получает номер кадра параметром. Внутри — `fw`/`fh` вместо `w`/`h`
      плюс смещение начала кадра; пропорции спрайта считаются от `fw`/`fh`
- [ ] Подключить по таблице то, что уже существует: `weapon_pistol`,
      `weapon_shotgun` (128×128), `sprite_enemy`, `sprite_enemy_serg`,
      `sprite_enemy_dead` (64×64). Остальные слоты в таблицу не входят
- [ ] `tests/test_assets.c` на `assets_parse_frame_size()` и на проверку
      кратности: корректное имя, имя без суффикса, суффикс не совпадает с
      ожидаемым, размер не кратен кадру. Добавить строку в
      `tests/CMakeLists.txt`

## Замечания

Число кадров в анимации — содержание файла, а не константа в коде: длину
берём из `cols`. Это безопасно, потому что после 06-05 спрайты
клиентские, и расхождение длины анимации между клиентами косметическое,
на симуляцию оно не влияет.

Размер кадра, наоборот, задаётся кодом и сверяется с именем файла. Так
файл, нарисованный не в том масштабе, отвергается сразу, а не растягивается
молча.

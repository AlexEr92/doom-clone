# 06-06 — Ввод на тик вместо ввода на кадр

**Этап:** 6 — Мультиплеерная логика локально
**Зависит от:** 06-01
**Блокирует:** 07-04, 08-02
**Оценка:** ~70 строк изменений

## Контекст

Сейчас ввод привязан к кадру, а не к тику симуляции:

- `main.c:170` — `input_end_frame()` вызывается **внутри** цикла фикс-шага,
  то есть все edge-события (`fire_pressed`, `use`, `switch1/2`) гасятся после
  первого под-шага
- `input.c:65` — `mouse_dx` накапливается за кадр, применяется в первом
  под-шаге, дальше нули
- `input.c:72-80` — `input_end_frame()` сбрасывает всё скопом

При 30 FPS на кадр приходится два тика, и второй получает пустой ввод.
Для сети нужен ровно один `PlayerInput` на тик, с номером тика — иначе
предсказание и реконсиляция не сойдутся.

## Что сделать

- [ ] Разделить: `InputState` (сырое состояние SDL, накапливается за кадр)
      и `PlayerInput` (снимок на тик, из 06-01)
- [ ] Битовая маска кнопок:
  ```c
  #define BTN_FORWARD (1u<<0)
  #define BTN_BACK    (1u<<1)
  #define BTN_LEFT    (1u<<2)   /* стрейф */
  #define BTN_RIGHT   (1u<<3)
  #define BTN_FIRE    (1u<<4)
  #define BTN_USE     (1u<<5)
  #define BTN_WEAPON1 (1u<<6)
  #define BTN_WEAPON2 (1u<<7)
  ```
- [ ] `PlayerInput input_sample(InputState *in, uint32_t tick);`
      вызывается один раз на тик внутри цикла фикс-шага, гасит edge-флаги
      только после того, как они попали ровно в один `PlayerInput`
- [ ] Поворот считает клиент вне фикс-шага: `mouse_dx` → приращение угла,
      в `PlayerInput` кладётся уже готовый абсолютный `angle`.
      Клавиши A/D (`ROT_SPEED`) — там же
- [ ] Убрать `in->mouse_dx` из `player_update()` (`player.c:58`): движение
      использует `angle` из `PlayerInput`
- [ ] `input_end_frame()` вызывать один раз за кадр, после всех тиков
- [ ] Обновить `tests/test_input.c` под разделение `InputState`/`PlayerInput`:
      кадр с несколькими тиками отдаёт edge-флаг (`BTN_FIRE`, `BTN_USE`) ровно
      одному `PlayerInput`, маска кнопок собирается из тех же клавиш, что и
      сейчас, а `player_update()` больше не читает `mouse_dx`

## Критерий готовности

- [ ] При искусственном ограничении FPS до 20 (`SDL_Delay` в цикле)
      выстрел по одиночному нажатию срабатывает ровно один раз, а не теряется
- [ ] Открытие двери по `E` не пропускается при низком FPS
- [ ] Чувствительность мыши на ощупь не изменилась
- [ ] Один кадр = N тиков → ровно N вызовов `input_sample()`,
      с последовательными номерами тиков

## Замечания

Решение «угол считает клиент, сервер принимает как есть» — стандартное
(так делает Quake): поворот должен быть мгновенным, задержка на RTT в
повороте камеры неприемлема. Сервер угол не валидирует, только ограничивает
частоту вводов. Для демо на LAN этого достаточно.

Edge-флаги нельзя просто размазать по всем тикам кадра: `fire_pressed`,
попавший в два тика подряд, даст два выстрела с одного нажатия.

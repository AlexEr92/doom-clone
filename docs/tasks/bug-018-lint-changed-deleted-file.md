# bug-018 — `lint.sh changed` отдаёт cppcheck удалённый `src/*.c` и падает

**Откуда:** замечено при работе над chore-011, которая правила ту же ветку
`changed` в `lint.sh`, но этот случай не покрывала
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~2–5 строк в `lint.sh`: ключ `--diff-filter=d` у двух команд
`git diff` в подстановке `mapfile` ветки `changed` (или фильтр по
существованию файла после `sort -u`)
**Приоритет:** низкий: срабатывает только при удалении или переименовании
`.c` (например, при выносе модуля), но тогда даёт ложный дефект на ревью

## Контекст

Ветка `changed` в `.claude/skills/lint/lint.sh` собирает список файлов из
`git diff --name-only HEAD -- 'src/*.c'`, `git diff --cached --name-only --
'src/*.c'` и `git ls-files --others --exclude-standard -- 'src/*.c'`. Обе
команды `git diff` перечисляют и удалённые пути. Такой путь попадает в
`files` и уходит в cppcheck, который не может его открыть.

Агент `reviewer` вызывает именно `lint.sh changed`, поэтому задача,
удаляющая или переименовывающая `.c`, получит на ревью ложный дефект.
`lint.sh all` не затронут: он берёт `src/*.c` глобом.

### Как воспроизвести

Проверено:

1. `mv src/hud.c /tmp/x`
2. `.claude/skills/lint/lint.sh changed`

Вывод:

```
проверяю: src/hud.c
cppcheck: error: could not find or open any of the paths given.
без SDL: чисто (симуляция и src/net_protocol.c)
rc=1
```

После проверки файл возвращают на место (`mv /tmp/x src/hud.c`).

## Что сделать

- [ ] Исключить удалённые файлы из списка ветки `changed`: `--diff-filter=d`
      у обеих команд `git diff` либо отбор по существованию файла
      (`[ -e "$f" ]`) после `sort -u`. Выбор за исполнителем; второй
      вариант страхует и от пути, удалённого уже после `git diff`
- [ ] Если после фильтрации список пуст (удалили единственный изменённый
      `.c`), вести себя как при «нет изменённых .c в src/»: напечатать
      сообщение, выполнить `check_sim`, не вызывать cppcheck без аргументов
- [ ] Добавить строку в `SKILL.md` (раздел про режим `changed`): удалённые
      файлы не проверяются

## Затрагиваемые файлы

- `.claude/skills/lint/lint.sh`
- `.claude/skills/lint/SKILL.md`

## Критерий готовности

- [ ] После `mv src/hud.c /tmp/x` команда `lint.sh changed` не упоминает
      `src/hud.c` в строке «проверяю», не печатает `could not find or open`
      и завершается кодом 0 (файл затем возвращён на место)
- [ ] При удалении одного `.c` и правке другого `lint.sh changed` проверяет
      только правленый
- [ ] Отслеживаемый изменённый `src/*.c` по-прежнему попадает в список ровно
      один раз, неотслеживаемый (chore-011) тоже
- [ ] `lint.sh all` и `lint.sh sim` ведут себя как раньше
- [ ] Шапка скрипта и `SKILL.md` описывают режим одинаково

## Замечания

- Третья команда в подстановке `mapfile`, `git ls-files --others`, нужна
  для новых неотслеживаемых файлов (chore-011); фильтр удалённых путей её
  не должен потерять.
- При переименовании через `git mv` или в индексе `git diff` с обнаружением
  переименований показывает только новый путь, так что старый в список не
  попадает; ломает именно удаление без индекса (`mv`, `rm`) и удаление,
  показанное как `D`.

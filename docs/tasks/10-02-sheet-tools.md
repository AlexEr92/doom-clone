# 10-02 — Инструменты подготовки и проверки листов кадров

**Этап:** 10 — Графика и арсенал
**Зависит от:** —
**Блокирует:** появление любого настоящего файла графики
**Оценка:** ~450 строк нового кода

## Контекст

Графику рисует генеративная модель, и то, что она отдаёт, ассетом ещё не
является. Она не умеет выдать холст 256×64 с точным `#FF00FF` и
однопиксельным краем: приходит большая картинка своего фиксированного
размера, со сглаженными контурами, розовой бахромой по границе с фоном и
неровно расставленными позами. Требования к готовому файлу перечислены в
`docs/assets-spec.md` — их обеспечивает инструмент, а не художник.

Приводить 78 файлов к сетке вручную нельзя, а привести их неодинаково —
хуже, чем не приводить вовсе: персонаж, у которого кадры выровнены каждый
по себе, подпрыгивает при беге, а его труп в последнем кадре смерти
всплывает к середине кадра.

Второй инструмент нужен потому, что часть требований подготовка не видит:
одинаковый ли рост у десяти скинов, сделанных десятью разными прогонами
модели, и на одном ли отступе от низа кадра стоят их ноги.

Проверка не должна жить в игре: ассеты меняются редко, а `assets_init()`
работает на каждом старте.

## Что сделать

- [ ] Довендорить `stb_image_write.h` и `stb_image_resize2.h` в `vendor/`
      рядом с уже лежащим `stb_image.h`
- [ ] Цель `BUILD_TOOLS` в `CMakeLists.txt`, по умолчанию выключенная,
      собирающая обе утилиты. Обычная сборка игры не меняется
- [ ] `tools/prepare_sheet.c`:
      ```
      prepare_sheet raw/marine.png --profile player --out assets/players/marine
      ```
  - сегментация: объекты на листе находятся по магентовому фону с
    допуском (сглаженная граница даёт целый диапазон розовых оттенков),
    сначала по рядам, затем по объектам внутри ряда
  - профиль задаёт ожидаемое число объектов в каждом ряду и файлы, в
    которые они идут: `player` (5 / 1 / 1 / 5), `weapon_fp`, `world_weapon`,
    `item`, `effect`, `face`, `icons` — по разделу «Промпты» в
    `docs/assets-spec.md`
  - несовпадение с профилем — ошибка со списком найденного, без догадок;
    ключ `--debug` сохраняет рядом картинку с обведёнными
    прямоугольниками, чтобы было видно, что склеилось или разъехалось
  - масштаб и привязка считаются **один раз на весь лист** по опорному
    объекту (у персонажа — стойка) и применяются ко всем кадрам
    одинаково: относительное движение внутри анимации сохраняется
  - уменьшение усреднением, затем приведение цвета: фон в точный
    `#FF00FF`, альфа в 0 или 255
  - запись полосок с именами по раскладке, включая суффикс `_<fw>x<fh>`
- [ ] `tools/check_sheets.c` — проверка того, что уже лежит в `assets/`:
  - имя содержит суффикс `_<fw>x<fh>`, размеры кратны кадру
  - нет пикселей с альфой строго между 0 и 255
  - нет пикселей, близких к `#FF00FF`, но не равных ему
  - непрозрачная область не касается краёв кадра, кроме нижнего
  - у каждого каталога из `assets/players/skins.txt` есть все пять файлов
    с одинаковым размером кадра
  - высота силуэта в `idle` расходится между скинами не более чем на
    заданный порог, и нижняя граница силуэта у всех на одном отступе от
    низа кадра
  - ожидаемое число кадров на анимацию — таблицей; расхождение это
    предупреждение, а не ошибка: длина анимации задаётся содержанием файла
  - ненулевой код возврата при любой ошибке, отчёт списком: файл, что не
    так, что ожидалось
- [ ] `raw/` в `.gitignore`: сырые картинки от модели в репозиторий не
      попадают, в нём лежит только результат подготовки

## Критерий готовности

- [ ] `cmake -S . -B build -DBUILD_TOOLS=ON && cmake --build build`
      собирает обе утилиты без предупреждений; обычная сборка без
      `BUILD_TOOLS` не изменилась
- [ ] Настоящая картинка от модели по промпту «Персонаж» из
      `docs/assets-spec.md` превращается одной командой в пять файлов
      правильного размера с точным фоном и жёсткой альфой
- [ ] В полученном `death_64x64.png` тело в последнем кадре лежит внизу,
      а не выровнено по центру кадра
- [ ] Лист, на котором две позы слиплись, отвергается с сообщением, а не
      режется пополам наугад; `--debug` показывает, где именно
- [ ] `check_sheets` по пустому или отсутствующему каталогу ассетов
      проходит успешно и ничего не печатает
- [ ] Специально испорченный файл (сглаженный край, розовый контур,
      некратный размер) отвергается с внятным сообщением

## Замечания

Альтернатива — Python с Pillow: кода вышло бы втрое меньше. Отвергнута
ради того, чтобы для работы с проектом хватало компилятора: `stb_image.h`
уже вендорен, а нужные для записи и масштабирования заголовки из того же
набора и подключаются так же.

В `pre-push` эту проверку вешать не стоит: ассеты меняются редко, а хук и
так занимает около девяти секунд. Место для неё — CI (`chore-001`) и
ручной прогон после получения новой пачки картинок.

Порог расхождения по росту силуэта подбирается по первой готовой пачке
скинов: сейчас угадывать число бессмысленно.

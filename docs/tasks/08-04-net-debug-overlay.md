# 08-04 — Отладочный оверлей сети (F3)

**Этап:** 8 — Качество netcode
**Зависит от:** 07-05
**Блокирует:** 09-06
**Оценка:** ~100 строк нового кода

## Контекст

Netcode невозможно отлаживать вслепую: «дёргается» — это может быть потеря
пакетов, расхождение предсказания, нехватка снапшотов для интерполяции или
просадка тикрейта сервера. Нужны цифры.

Задачу стоит делать **до** 08-02, а не после — она окупается сразу.

- [ ] Опция запуска `--netlag <ms> --netloss <pct>` — искусственные задержка

      Это основной инструмент проверки сетевых требований

      `SDL_CreateRenderer()` читает подсказку `SDL_HINT_RENDER_VSYNC`, и

      снимает vsync (см. «Замечания»). Флаг делает то же из командной
      строки — `SDL_SetHint(SDL_HINT_RENDER_VSYNC, "0")` до
      `SDL_CreateRenderer()` — и виден в `--help`

## Замечания

Vsync без флага: под Xvfb заголовок окна показывает около 63 FPS, а с
`SDL_RENDER_VSYNC=0 driver.sh start` на той же сборке — 270–370 (замер в
09-07; `driver.sh` передаёт игре своё окружение). Проверено только на
Linux с программным рендерером SDL под Xvfb; на других платформах и
рендерерах подсказка та же, но не измерялась.

Встроенные `--netlag`/`--netloss` заметно быстрее в итерациях, чем `tc`:
не требуют root и работают одинаково на всех платформах.

`net_peer_rtt()` — RTT, который ENet меряет по подтверждениям, и в него
входит период опроса дальней стороны: при опросе раз в тик на loopback он
16–17 мс, а не около нуля. Критерий «`--netlag 150` показывает ~150 мс»
надо читать с этой поправкой.

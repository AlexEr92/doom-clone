# chore-002 — Убрать неработающий тернарник в `text_width()`

**Откуда:** найдено `.claude/skills/lint/lint.sh strict`
(`duplicateExpressionTernary`, `src/game.c:137`)
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~2 строки изменений

## Контекст

`text_width()` (`src/game.c:133-140`) считает ширину строки для
`draw_centered()`:

```c
static int text_width(const char *s, int scale)
{
    int w = 0;
    for (const char *p = s; *p; p++) {
        w += (*p == ' ') ? 4 * scale : 4 * scale;
    }
    return w - scale;
}
```

Обе ветки тернарника дают `4 * scale` — условие `*p == ' '` ничего не
решает, cppcheck отмечает это как `duplicateExpressionTernary`. По виду
код писался с намерением дать пробелу другую ширину продвижения, чем у
буквы, но так и не был доведён до конца.

Смотреть на это в отрыве от `draw_text()` (`src/game.c:120-131`), которая
и рисует те же строки, нельзя — именно она задаёт, чему на самом деле равна
ширина символа на экране:

```c
static void draw_text(Framebuffer *fb, int x0, int y0, const char *s, uint32_t color, int scale)
{
    int x = x0;
    for (const char *p = s; *p; p++) {
        if (*p == ' ') {
            x += 4 * scale;
            continue;
        }
        draw_char(fb, x, y0, *p, color, scale);
        x += 4 * scale;
    }
}
```

`draw_text()` продвигает курсор на `4 * scale` для пробела и для буквы
одинаково — `draw_char()` для пробела просто не вызывается, но курсор
идёт вперёд на ту же величину. Иными словами, нынешний (нерабочий)
тернарник в `text_width()` уже согласован с фактическим рендером:
результат функции корректно предсказывает ширину строки, которую
нарисует `draw_text()`, при любом сочетании букв и пробелов — в
частности, `draw_centered()` (`src/game.c:142-146`) центрирует текст
верно уже сегодня.

Если бы «намерение» было исправлено — например, пробелу дали бы ширину
`2 * scale` — `text_width()` разошлась бы с `draw_text()`: подсчитанная
ширина строки перестала бы совпадать с реально отрисованной, и
`draw_centered()` начала бы смещать любую фразу с пробелом относительно
центра экрана на разницу в ширине умноженную на число пробелов. Чтобы
починить «намерение», а не просто убрать мёртвый код, пришлось бы менять
обе функции согласованно — это отдельное решение о внешнем виде шрифта,
которое здесь никто не запрашивал.

## Что сделать

- [ ] Схлопнуть тернарник в `text_width()` до безусловного
      `w += 4 * scale;` — поведение не меняется, убирается только мёртвое
      выражение
- [ ] Не трогать `draw_text()` — она уже ведёт себя так, как теперь
      явно записано в `text_width()`

## Замечания

Не расширять задачу до «сделать пробелу другую ширину» — это отдельное
изменение внешнего вида текста (шире или уже некоторые фразы, другая
центровка HUD/меню), которое никто не просил и которое требует
согласованной правки `draw_text()` и `text_width()` вместе, а не только
удаления мёртвого выражения. Если такая правка когда-нибудь понадобится —
заводить новую задачу отдельно.

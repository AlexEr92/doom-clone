# 08-05 — Лаг-компенсация хитскана

**Этап:** 8 — Качество netcode
**Зависит от:** 08-03, 05-04
**Блокирует:** 09-05 (баланс DM)
**Оценка:** ~150 строк нового кода
**Приоритет:** высокий — обязательна для deathmatch

## Контекст

Из-за интерполяции (08-01) клиент видит противников на ~100 мс в прошлом,
плюс ввод идёт до сервера ещё RTT/2. Стреляя точно в цель, игрок промахнётся
на серверной стороне: там противник уже сместился.

При скорости игрока `MOVE_SPEED 3.0` клетки/с и суммарной задержке 150 мс
цель успевает сместиться на 0.45 клетки — это больше её радиуса (0.2).
То есть **без компенсации попадания по движущимся игрокам практически
не проходят вообще**, а в deathmatch оба оружия — хитскан.

## Что сделать

- [ ] История на сервере:
  ```c
  #define LAGCOMP_HISTORY 64   /* ~1 с при 60 Гц */
  typedef struct {
      uint32_t tick; double time;
      struct { float x, y; int alive; } players[MAX_PLAYERS];
      struct { float x, y; int alive; } enemies[MAX_ENEMIES];
  } WorldSnapshotLite;
  ```
      Заполняется каждый тик в `server_tick()`.
      При 10 игроках: 64 × (10×12 + 32×12) ≈ 32 КБ — приемлемо
- [ ] При `BTN_FIRE` от клиента: вычислить целевое время
      `now - (rtt/2 + INTERP_DELAY)`, найти пару кадров, интерполировать
      позиции сущностей
- [ ] Подменить позиции на время вызова `world_raycast()` (05-04),
      посчитать попадание, восстановить
- [ ] Ограничить откат: не более 250 мс — иначе клиент с гигантским пингом
      получает возможность стрелять по «призракам»
- [ ] Урон применяется к текущему состоянию цели, а не к историческому
      (цель могла умереть за это время — проверять `alive` на момент
      применения)
- [ ] Не компенсировать выстрелы по игрокам с активной неуязвимостью
      после респавна (09-02) — иначе откат «воскресит» их в уязвимом виде
- [ ] Флаг `--no-lagcomp` для сравнения и отладки

## Затрагиваемые файлы

`net_server.c/.h`, `raycast_world.c`, `weapon.c`

## Критерий готовности

- [ ] При 150 мс задержки попадания по движущейся цели ощущаются честно:
      прицел на противнике = попадание
- [ ] Откат не позволяет попасть по цели, которая уже 500 мс как за углом
- [ ] Урон не наносится уже мёртвой или неуязвимой цели
- [ ] Без флага и с `--no-lagcomp` разница очевидна на глаз при 150 мс
- [ ] 10 игроков + история 1 с не дают заметной нагрузки на сервер

## Замечания

Классический побочный эффект (есть во всех играх с лаг-компенсацией):
жертва иногда получает урон, уже забежав за угол — «меня убили за стеной».
Это неизбежный компромисс: либо промахивается стрелок, либо страдает жертва.
В deathmatch выбирают в пользу стрелка — иначе стрельба не работает.

Ограничение отката в 250 мс — и защита от читов, и защита от эффекта выше:
чем больше окно, тем чаще жертвы умирают «за укрытием».

Разброс дробовика (`weapon.c:84`) крутится на сервере уже после отката,
на самой компенсации это не сказывается — но означает, что переигрывать
выстрел при реконсиляции клиент не может в принципе (см. 08-02).

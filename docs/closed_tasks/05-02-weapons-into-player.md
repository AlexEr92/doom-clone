# 05-02 — Перенести `WeaponSystem` внутрь игрока

**Этап:** 5 — Развязка симуляции и рендера
**Зависит от:** 05-01
**Блокирует:** 06-02
**Оценка:** ~50 строк изменений

## Контекст

`main.c:27` держит `WeaponSystem ws` в структуре `World` — то есть оружие,
патроны и кулдауны общие на весь мир. При нескольких игроках они обязаны
быть персональными.

## Что сделать

- [x] Перенести `WeaponSystem weapons` из `World` (`main.c:20-30`) в
      `PlayerState`
- [x] `weapon_system_init()` вызывать из `player_init()`, а не из
      `world_load()` (`main.c:39`)
- [x] Сигнатуры на `PlayerState *`, а не на пару `(Player*, WeaponSystem*)`:
  - `weapon_try_fire(PlayerState *p, EnemyList *el, ...)`
  - `weapon_update(PlayerState *p, double dt)`
  - `weapon_switch(PlayerState *p, int idx)`
  - `item_update(..., PlayerState *pl, ...)` — убрать отдельный `ws`
- [x] `hud_draw(fb, const PlayerState *pl)` — оружие берёт из игрока
- [x] `main.c:123-125` (заголовок окна с патронами) и `main.c:152-153`
      (переключение оружия) — на локального игрока

## Затрагиваемые файлы

`player.h`, `weapon.h/.c`, `item.h/.c`, `hud.h/.c`, `main.c`

## Критерий готовности

- [x] `grep -n "WeaponSystem" src/*.h` находит его только в `weapon.h`
      (определение) и `player.h` (поле)
- [x] Патроны, кулдаун и анимация оружия работают как раньше
- [x] Подбор патронов пополняет оружие того игрока, который подобрал
      (проверяется на одном игроке; полноценно — в 06-04)

## Замечания

`Weapon.anim` — таймер анимации отдачи, чисто визуальный. Оставить в
`WeaponSystem`: он персональный, дёшев (1 float) и в снапшот его слать не
нужно — клиент заведёт свой по событию выстрела (см. 07-06).

## Закрыто

2026-08-22 — `WeaponSystem` переехал из `World` (`main.c`) в поле
`PlayerState.weapons`, `weapon_system_init()` вызывается из
`player_init()`. `weapon_switch()`, `weapon_update()` и `weapon_try_fire()`
принимают `PlayerState *`, `item_update()` и `hud_draw()` — без отдельного
`WeaponSystem *`. `main.c` берёт оружие у локального игрока: и заголовок
окна с патронами, и переключение по клавишам 1/2, и отрисовка HUD.

Направление зависимости между `player.h` и `weapon.h` развёрнуто: поле в
структуре требует полного типа, поэтому `player.h` включает `weapon.h`, а
`weapon.h` не включает ничего и объявляет `struct PlayerState`,
`struct EnemyList`, `struct SpriteList` вперёд. `SpriteList` и `EnemyList`
получили теги структур, чтобы это было возможно; `hud.h` включает
`assets.h` напрямую — раньше `Texture` приходил в него транзитивно через
`weapon.h`.

Проверено: сборка без предупреждений под `-Wall -Wextra`,
`clang-format --dry-run -Werror` чист, `driver.sh smoke` проходит все шесть
проверок, включая выстрел (50 → 49 патронов).

Подбор патронов проверен двумя способами. В игре: три выстрела из
пистолета (50 → 47), проход по карте до боеприпаса — 47 → 50 (12 патронов
с обрезанием по `max_ammo`), воспроизведено с чистого запуска. Отдельно —
одноразовой программой, слинкованной с объектными файлами игры: два
игрока, боеприпас лежит под первым, `item_update()` пополняет пистолет
именно ему (10 → 22), второй игрок не меняется, повторный вызов ничего не
даёт, дробовик не затронут.

## Что происходит

`assets/players/marine/death_64x64.png` — лист из пяти кадров (320×64):
падение от первого кадра к пятому, где тело лежит на полу. `sprite_render()` (`sprite.c`)
берёт кадр так:

```c
const uint32_t *frame = texture_frame(tex, 0, sp->view);
```

Столбец всегда нулевой, и убитый враг (`SPRITE_ENEMY_DEAD`, выбирается в
`enemy_sprite_type()` по `ESTATE_DEAD`) навсегда остаётся в первой
фазе падения — «в промежуточном положении».

Полная анимация смерти — предмет 10-03 (часы по идентификатору, `ANIM_DEATH`
залипает на последнем кадре). Но 10-03 — ~200 строк и целая клиентская
подсистема, а труп по последнему кадру не требует часов вовсе: проигрывать
нечего, нужен именно последний.

## Как воспроизвести

1. Запустить игру из корня проекта (`cmake --build build --target run`);
   файл `assets/players/marine/death_64x64.png` должен лежать на месте.
2. Убить импа (`E` на карте) выстрелами из пистолета.
3. Труп стоит в позе первого кадра листа, а не лежит.

- [ ] У процедурной текстуры один столбец, так что без файла результат тот

## Замечания

Временная мера: 10-03 заменяет этот код выбором кадра по `Sprite.frame` и
делает `SPRITE_ENEMY_DEAD` ненужным. Тогда строка из этой задачи уйдёт
вместе со своей веткой; ничего сверх неё в 10-03 менять не нужно. Если
10-03 будет сделана раньше этой, эту закрыть попутно.

Какой именно лист у трупа сержанта — `bug-012`. Она вводит второй тип
трупа, а условие здесь проверяет только `SPRITE_ENEMY_DEAD`, поэтому
последний столбец для нового типа — часть её работы.

## Закрыто

2026-10-16 — исправлено, как в задаче: `sprite_render()` берёт у
`SPRITE_ENEMY_DEAD` столбец `tex->cols - 1`, у остальных типов — по-прежнему
0. Ряд выбирается как раньше, по `Sprite.view`.

Проверено в игре: имп с восточного края карты убит из дробовика, кадр снят
вблизи. До правки труп стоял в позе первого кадра `death_64x64.png`
(отброшенный выстрелом, ноги над полом), после — лежит, как на пятом кадре.
Без файла труп — прежний процедурный: у него один столбец, и `cols - 1`
совпадает с нулём.

`bug-012` добавляет второй тип трупа и в своей спецификации распространяет
на него то же правило.

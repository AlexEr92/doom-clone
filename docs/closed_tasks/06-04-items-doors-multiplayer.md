# 06-04 — Предметы и двери на N игроков

**Этап:** 6 — Мультиплеерная логика локально
**Зависит от:** 06-02
**Блокирует:** —
**Оценка:** ~60 строк изменений

## Контекст

Две связанные проблемы:

1. `item_update()` (`item.c:55-71`) проверяет подбор только одним игроком.
2. Позиция предмета живёт **в спрайте**: `item_add()` (`item.c:19-20`)
   оставляет `it->x/y` нулями, а `item_update()` (`item.c:62-65`) читает
   `sp->x`, `sp->y`. Поскольку на этапе 6 спрайты становятся клиентской
   сущностью (задача 06-05), симуляция потеряет источник координат.

## Что сделать

- [ ] `item_add()` — принимать и сохранять `x, y`; убрать зависимость от
      `sprite_id` в логике (поле можно удалить целиком)
- [ ] `item_update()`:
  ```c
  void item_update(ItemList *il, PlayerState *players, int count, EventQueue *ev);
  ```
      цикл по предметам × игрокам; предмет достаётся первому подошедшему
      по возрастанию `id` (детерминизм при одновременном подборе)
- [ ] `apply_pickup()` (`item.c:24-53`) — на `PlayerState`, оружие берётся
      из игрока (после 05-02); вместо `audio_play_volume()` — событие
      `EV_PICKUP` с координатами предмета
- [ ] Дверь, открытая одним игроком, открыта для всех — уже так, состояние
      лежит в `DoorList`, менять не надо
- [ ] Обновить `tests/test_item.c` и `tests/test_door.c`: предмет достаётся
      ровно одному из двух подошедших одновременно игроков (меньший `id`), а
      дверь держит открытой любой из нескольких `DoorOccupant` — и закрывается
      только когда проём покинули все

## Затрагиваемые файлы

`item.h/.c`, `door.h/.c`, `world.c`, `tests/test_item.c`, `tests/test_door.c`

## Критерий готовности

- [ ] `grep -n "sprite" src/item.c` — пусто
- [ ] Два игрока подходят к аптечке одновременно → подбирает ровно один
- [ ] Дверь, открытая игроком 0, проходима для игрока 1
- [ ] Одиночная игра: все предметы подбираются как раньше

## Замечания

Двери на N игроков уже работают: `world_step()` (06-02) вызывает
`door_try_use()` в цикле по игрокам с нажатым `use` и собирает
`DoorOccupant` по всем живым. Здесь остаётся только закрепить это тестом —
дверь держит открытой любой из нескольких занявших проём.

## Закрыто

2026-08-27 — предмет лежит в мире собственными координатами: `item_add()`
принимает `x, y`, `Item` хранит их и лишился `sprite_id`, а `item.c` о
спрайтах не знает вовсе — `grep -n "sprite" src/item.c` пуст.

`item_update(ItemList *il, PlayerState *players, int count, EventQueue *evq)`
обходит предметы по игрокам и ничего не возвращает: что случилось за тик,
видно по `EV_PICKUP` в очереди. Предмет достаётся первому подошедшему по
возрастанию `id`, потому что при одновременном подборе результат не вправе
зависеть от порядка обхода. Игрок, которому предмет не нужен — с полным hp
или полным боезапасом, — не подбирает его и не мешает подобрать следующему.
Подбирает только тот, кто `active && alive && hp > 0`: свободный слот и труп
стоят на предмете ровно так же, как живой, и оба должны пройти мимо.

Спрайт подобранного предмета гасит `world.c` по таблице `World.item_sprite`,
которую заполняет загрузка карты. Связь предмета с рендером живёт теперь
рядом с рендерным списком, а не внутри сущности симуляции, и уезжает вместе
с таблицей в 06-05.

Двери не изменились: состояние лежит в `DoorList` и общее для всех, а
`world_step()` (06-02) уже вызывает `door_try_use()` по всем игрокам с
нажатым `use` и собирает `DoorOccupant` по всем живым.

`tests/test_item.c` переписан без `SpriteList`: предметы расставляются
координатами, игроков трое. К прежним сценариям добавлены подбор двумя
игроками в одном тике (забирает `id` 0), отказ первого в пользу второго,
по предмету каждому из стоящих врозь, отказ неактивному, неживому и игроку с
нулевым hp, а также содержимое `EV_PICKUP`. В `tests/test_door.c` добавлены
дверь, которую держат несколько занявших проём и которая закрывается лишь
после ухода последнего, и дверь, открытая одним игроком и обслуживающая
другого — тот стоит в проёме и закрывает её за собой с другой стороны.

`docs/architecture.md` и `CLAUDE.md` больше не называют `SpriteList`
источником истины для позиций предметов: из известных ограничений остались
враги, которых `enemy.c` каждый тик копирует в спрайты.

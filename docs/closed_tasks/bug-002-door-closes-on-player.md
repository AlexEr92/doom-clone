# bug-002 — Дверь закрывается в стоящем в проёме

**Откуда:** замечено при разборе `door_update_all()` для задачи 06-04
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~25 строк изменений

## Что происходит

Дверь автоматически закрывается через `DOOR_OPEN_TIME` (4 с), не проверяя,
занят ли проём (`door.c`, ветка `case DOOR_OPEN` в `door_update_all()`):

```c
case DOOR_OPEN:
    d->timer -= (float)dt;
    if (d->timer <= 0.0f) {
        d->state = DOOR_CLOSING;
    }
    break;
```

Если игрок в этот момент стоит в клетке двери, `openness` уходит ниже 0.5,
`door_is_blocking()` начинает возвращать 1, и клетка становится стеной
вместе с игроком внутри. `try_move()` после этого не выпускает его ни в
одну сторону — коллизия видит стену со всех сторон.

Врагов это касается ровно так же: `move_towards()` использует ту же
проверку `map_is_wall_door()`.

## Как воспроизвести

1. Открыть дверь `D` в `level1.txt` по `E`
2. Встать точно в клетку двери и не двигаться 4 секунды
3. Попробовать выйти

Игрок заперт внутри геометрии; выйти можно только повторным `E`, и то не
всегда — `door_try_use()` ищет дверь по клетке перед игроком и по клетке
под ним, так что спасает случайно.

## Что сделать

- [ ] Добавить проверку занятости клетки двери перед переходом в
      `DOOR_CLOSING`: если в ней есть живой игрок или враг — сбросить
      таймер в `DOOR_OPEN_TIME` и остаться открытой
- [ ] Ту же проверку применить в `DOOR_CLOSING`: если кто-то вошёл в
      проём во время закрытия, вернуться в `DOOR_OPENING`
- [ ] Радиус занятости брать не точкой, а с учётом `PLAYER_RADIUS` —
      игрок, стоящий на границе клетки, тоже блокирует закрытие
- [ ] `door_update_all()` понадобится доступ к списку игроков и врагов —
      сейчас он принимает только `DoorList` и `dt`

## Критерий готовности

- [ ] Дверь не закрывается, пока в её клетке кто-то стоит
- [ ] Дверь, начавшая закрываться, открывается обратно при входе в проём
- [ ] Пустая дверь по-прежнему закрывается через 4 с
- [ ] Игрок ни при каких действиях не оказывается замурован
- [ ] `driver.sh smoke` проходит

## Замечания

Смена сигнатуры `door_update_all()` пересекается с задачей 06-01, которая
собирает вызовы в `world_step()`. Если 06-01 к тому моменту сделана,
список игроков берётся из `World`; если нет — передавать параметром.

С одним игроком баг ловится редко, с десятью в deathmatch — постоянно,
поэтому чинить стоит до этапа 9, а не после.

## Закрыто

2026-08-22 — `door_update_all()` принимает массив `DoorOccupant` (позиции
живых игроков и врагов) и проверяет занятость клетки кругом
`PLAYER_RADIUS`: в `DOOR_OPEN` занятая дверь сбрасывает таймер, в
`DOOR_CLOSING` — возвращается в `DOOR_OPENING`. Передаются именно
координаты, а не списки сущностей, чтобы `door.c` не тянул `enemy.h` и
через него SDL. Список собирает `world_door_occupants()` в `main.c` —
с 06-01 переедет в `world_step()`.

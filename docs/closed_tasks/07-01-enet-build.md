## Контекст

Нужен UDP с надёжными каналами, фрагментацией, учётом RTT и обнаружением
разрывов. SDL2_net этого не даёт (голые сокеты), писать своё — отдельный
проект. ENet — ~10k строк на C, MIT, без зависимостей.

Задача независима от остальных — можно делать параллельно с этапами 5–6.

## Что сделать

- [ ] ENet — submodule `vendor/enet/` на релизном теге апстрима
      (`github.com/lsalzman/enet`), собирается его собственным
      `CMakeLists.txt` через `add_subdirectory` и линкуется статически.
      Системный пакет не ищется: путь к ENet один на всех платформах
- [ ] Пустой `vendor/enet/` (клон без `--recurse-submodules`) —
      конфигурация останавливается с подсказкой `git submodule update
      --init`, а не падает на непонятной ошибке
- [ ] На Windows ENet требует линковки `ws2_32` и `winmm` — добавить условно
- [ ] Опция `-DENABLE_MULTIPLAYER=ON/OFF` (по умолчанию ON): при OFF сетевые
      файлы не компилируются и ENet не собирается, собирается чистая одиночная
      игра. Полезно и как страховка, и для платформ, где ENet не собрать
- [ ] README: ENet в зависимостях, `git submodule update --init`,
      `-DENABLE_MULTIPLAYER=OFF`
- [ ] Проверить сборку: Linux, macOS, Windows (MSYS2 и MSVC)

## Затрагиваемые файлы

`CMakeLists.txt`, `.gitmodules`, `vendor/enet/`, `README.md`

## Критерий готовности

- [ ] `git submodule update --init && cmake -S . -B build && cmake --build
      build` проходит на Linux без установленного в системе ENet
- [ ] `cmake -S . -B build -DENABLE_MULTIPLAYER=OFF` собирает игру, не
      трогая ENet: проходит и с пустым `vendor/enet/`, в дереве сборки нет
      `vendor/enet/`, строка линковки `doom-clone` не упоминает `enet`,
      `ctest -N` не знает теста `enet`. `ldd` здесь ничего не различает —
      ENet линкуется статически
- [ ] С пустым `vendor/enet/` конфигурация останавливается и называет
      команду, которая его заполнит

## Замечания

**Почему submodule, а не системный пакет.** ENet есть в пакетных
менеджерах всех целевых платформ, но поиск системного пакета ничего не
даёт этому проекту и обходится дорого:

- у всех клиентов матча должен быть один ENet; пакеты дают разные версии
  на разных платформах, submodule — закреплённый тег везде;
- статически слинкованный бинарь можно отдать другому игроку, не требуя
  поставить `libenet`;
- пакеты ENet устроены по-разному (CMake-конфиг vcpkg, `libenet.pc` у apt,
  Homebrew и MSYS2, где-то только заголовок и библиотека) — поиск
  разрастается в цепочку из трёх вариантов, которую на одной машине не
  проверить;
- два пути к одной библиотеке — две конфигурации, которые надо держать
  рабочими, без выгоды от второй.

Обновления безопасности при этом не приходят сами: новую версию ENet
подтягивают переводом submodule на следующий тег. ENet меняется редко.

ENet требует `enet_initialize()` при старте и `enet_deinitialize()` при
выходе — это уже часть 07-02, но про atexit-регистрацию стоит помнить сразу.

## Закрыто

2026-10-17 — ENet подключён submodule'ом `vendor/enet/` на теге v1.3.18 и
собирается апстримным `CMakeLists.txt` через `add_subdirectory(...
EXCLUDE_FROM_ALL)`; игра и тесты получают его через INTERFACE-цель
`doom_enet`, которая на Windows добавляет `ws2_32` и `winmm`. Системный
пакет не ищется и опции `VENDOR_ENET` нет — почему, сказано в «Замечаниях».
`-DENABLE_MULTIPLAYER=OFF` не конфигурирует ENet вовсе.

Апстриму понадобились две поправки снаружи, на цели `enet`:
`C_EXTENSIONS ON` — под строгим `-std=c11` проекта glibc прячет
`getaddrinfo()`, и `unix.c` не компилируется; `-w` на GCC/Clang — иначе
`-Wall -Wextra` проекта дают в `vendor/enet/` семь предупреждений. Его
`project(enet)` без списка языков включает C++, так что сетевой сборке
нужен компилятор C++: это записано в README (Fedora — `gcc-c++`) и в
requirements.md, раздел 1.

Сверх «Что сделать» — `tests/test_enet.c`: игра ENet пока не вызывает, и
без теста сломанный include-путь или линковка проявились бы только в 07-02.
Тест сверяет `ENET_VERSION` с `enet_linked_version()`, вызывает
`enet_initialize()` и поднимает хост на 127.0.0.1.

Проверено на Linux: сборка по умолчанию без ENet в системе, `check.sh` —
всё «ок», ctest 13/13; OFF-сборка — 12 тестов, `vendor/enet/` в дереве
сборки нет; с пустым `vendor/enet/` конфигурация называет
`git submodule update --init vendor/enet`; `cmake --install` ставит
только `doom-clone`. Сборка на macOS и Windows здесь не проверена, ветка
`WIN32` написана по документации vcpkg и апстрима — её проверит CI
(chore-001).

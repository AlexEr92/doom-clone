# bug-008 — `assets_load_png()` теряет пиксели слота, который замещает

**Откуда:** замечено при подключении файловых текстур в
`10-01-sprite-sheet-loader.md`
**Зависит от:** —
**Блокирует:** —
**Оценка:** ~5 строк изменений, только `assets.c`

## Что происходит

Комментарий в заголовке обещает замену на месте:

```c
/* Load PNG from path into tex (replaces existing). Returns 0 on success. */
int assets_load_png(Texture *tex, const char *path);   /* assets.h */
```

Реализация (`assets.c`) присваивает `tex->pixels = px`, не освободив то, что
там лежало. Слоты `Assets` к моменту загрузки уже заполнены генераторами, то
есть «замена существующего» — ровно тот случай, ради которого функция и
написана, и ровно тот, в котором она теряет буфер.

Сегодня это не течёт: единственный вызывающий — `assets_load_sheet()`, и он
передаёт обнулённую локальную `Texture`, а слот меняет через
`texture_free()` + присваивание. То есть дефект целиком в контракте: любой
следующий вызывающий, поверивший комментарию, получит утечку размером с
текстуру.

## Что сделать

- [ ] Либо освобождать прежние пиксели в начале `assets_load_png()` через
      `texture_free()` — тогда комментарий становится правдой, а вызов с
      неинициализированной `Texture` начинает требовать обнуления, что уже
      и так делают все вызывающие
- [ ] Либо переписать комментарий: функция заполняет `Texture`, владельцем
      прежнего буфера остаётся вызывающий

## Затрагиваемые файлы

- `src/assets.c`, `src/assets.h`

## Критерий готовности

- [ ] Комментарий в `assets.h` и поведение `assets_load_png()` описывают
      одно и то же
- [ ] `ctest --test-dir build --output-on-failure` зелёный

## Закрыто

2026-10-18 — выбран первый вариант с одной поправкой: `assets_load_png()`
освобождает прежние пиксели через `texture_free()` не в начале, а после
того, как новая картинка прочитана и переупакована. Файл, который не
читается, не отнимает у слота текстуру — тот же контракт, что у
`assets_load_sheet()`. Комментарий в `assets.h` говорит именно это: прежний
буфер освобождается, поэтому `tex` должен быть обнулён или владеть своими
пикселями, а при отказе `tex` остаётся как был.

В `tests/test_assets.c` два теста: `test_png_replaces_what_the_texture_held`
(загрузка поверх заполненной текстуры даёт размеры и пиксели картинки) и
`test_png_that_fails_leaves_the_texture_alone` (отказ не трогает ни
указатель, ни пиксели, ни размеры; он же падает, если освобождение
перенести в начало функции). Само освобождение юнит-тест не видит, его
видит valgrind: `valgrind --leak-check=full build/tests/test_assets` с
исправлением — ни одной утечки, против прежнего `assets.c` — 16 384 байта
definitely lost в первом из тестов. В `ctest` это ловит сборка
с санитайзерами из `chore-005-sanitizer-build.md`.

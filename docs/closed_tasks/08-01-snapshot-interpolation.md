# 08-01 — Буфер снапшотов и интерполяция

**Этап:** 8 — Качество netcode
**Зависит от:** 07-05
**Блокирует:** —
**Оценка:** ~180 строк нового кода

## Контекст

Снапшоты приходят на 20 Гц, рендер идёт на 60+ FPS. Без интерполяции чужие
игроки и враги двигаются рывками по три кадра.

Приём: рендерить не последнее состояние, а состояние на 100 мс в прошлом,
интерполируя между двумя снапшотами, которые его окружают. Задержка в 2
снапшота даёт запас на потерю одного пакета.

## Что сделать

- [ ] Кольцевой буфер снапшотов на клиенте:
  ```c
  #define SNAPSHOT_HISTORY 8
  typedef struct {
      MsgSnapshot snaps[SNAPSHOT_HISTORY];
      double      recv_time[SNAPSHOT_HISTORY];
      int         head, count;
  } SnapshotBuffer;
  ```
- [ ] `#define INTERP_DELAY 0.100` — время рендера = `now - INTERP_DELAY`
- [ ] Поиск пары снапшотов вокруг целевого времени + коэффициент `t ∈ [0,1]`
- [ ] Интерполяция по сущностям:
  - позиции — линейно
  - `angle` — по **кратчайшей дуге**: `a + wrap_pi(b - a) * t`
    (наивный lerp даст оборот на 360° при переходе через ±π)
  - `hp`, состояние ИИ, оружие — не интерполируются, берутся из старшего
    снапшота
  - сущность, отсутствующая в одном из снапшотов (спавн/деспавн),
    не интерполируется
- [ ] Результат интерполяции идёт **только в рендер** — в
      `sprites_build_from_world()` (06-05); симуляционный `World` не трогаем
- [ ] Экстраполяция при нехватке снапшотов: продолжить движение по последней
      скорости, не дольше 250 мс, дальше — заморозить

## Затрагиваемые файлы

`net_client.c/.h`, `world.h` (буфер для рендер-состояния), `main.c`

## Критерий готовности

- [ ] Чужой игрок движется плавно при 20 Гц снапшотов и 60 FPS
- [ ] Искусственная потеря 10% пакетов не даёт видимых рывков
- [ ] Игрок, поворачивающийся через границу ±π, не делает оборота
- [ ] Локальный игрок интерполяцией **не** затрагивается (он пойдёт через
      предсказание, 08-02)

## Замечания

Проверять с `tc netem`:
```bash
sudo tc qdisc add dev lo root netem delay 75ms 10ms loss 10%
sudo tc qdisc del dev lo root                     # снять
```

100 мс задержки означает, что вы видите противников на 100 мс в прошлом.
Это плата за плавность и стандартный компромисс; частично компенсируется
лаг-компенсацией на сервере (08-05).

## Закрыто

2026-10-19 — клиент рисует чужих игроков и врагов на `INTERP_DELAY`
(100 мс) в прошлом, между двумя снапшотами из буфера.

- Буфер и интерполяция — новый модуль `src/net_interp.c/.h` без SDL и
  сокетов: `SnapshotBuffer` на `SNAPSHOT_HISTORY` (8) снапшотов,
  `interp_push()` и `interp_view()`; тест — `tests/test_net_interp.c`.
  `world.h` не тронут: рендер-состояние — не симуляция. Вид — отдельный
  `World`, который `client_view()` строит раз в кадр; в `GameSession`
  появился слот `view` (одиночная игра и хост отдают сам мир), и `main.c`
  передаёт вид только в `sprite_anim_update()` и
  `sprites_build_from_world()`.
- `INTERP_DELAY_MS`/`INTERP_DELAY`, `INTERP_EXTRAPOLATE` (0.25 с) и
  `SNAPSHOT_HISTORY` — в `config.h`, с `_Static_assert`, что буфера хватает
  на задержку при 60 снапшотах в секунду; строка в `requirements.md` §5.
- Время интерполяции — тики сервера. `recv_time` служит только для оценки
  сдвига часов клиента относительно сервера: сглаживание на 0.1 за опрос,
  из снапшотов одного опроса считается самый свежий, скачок больше 0.5 с
  принимается сразу. Пары по моментам приёма давали бы неровную скорость
  из-за джиттера и опроса раз в кадр.
- «Из старшего снапшота» прочитано как «из раннего в паре», то есть
  последнего не позже рисуемого момента. Двигается тот, кто есть в обоих
  снапшотах и жив в раннем; респавн — прыжок; экстраполяция — только для
  живых в двух последних.
- Чтобы не дублировать разбор `NetPlayer`/`NetEnemy`, из
  `snapshot_apply()` выделена `snapshot_apply_characters()`.
- `tc netem` не запускался: ему нужен root на loopback машины, а
  непривилегированные user namespace в системе закрыты. Потери и задержка
  проверены моделью в `test_other_player_moves_smoothly_through_loss_and_jitter`
  (20 Гц, 60 кадров/с, 75 ± 10 мс, 10 % потерь, не больше двух подряд:
  худший кадр отклоняется на 11–14 % при пороге 25 %) и вживую через
  UDP-ретранслятор с теми же задержкой и потерями. С ним
  `net_bot watch` дал в виде движение в 894 кадрах из 899 и 1 рывок —
  остановку на углу, а в сыром мире 531 рывок. Три и больше потерь
  подряд дают на кривой ступеньку при возврате из экстраполяции
  (`architecture.md`, «Интерполяция»); её сглаживание — feat-005.
- Новый режим ручного инструмента: `net_bot watch ID [SECONDS]` —
  движение игрока по кадрам в виде и в сыром мире.
- В `NOSDL=` `lint.sh` `net_interp.c` не внесён; это теперь часть
  chore-013.

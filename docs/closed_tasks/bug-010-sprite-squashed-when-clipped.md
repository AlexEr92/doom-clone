# bug-010 — Спрайт сплющивается, когда не помещается в экран сверху

**Откуда:** замечено при исправлении `bug-009-sprite-aspect-ignores-fov.md`

**Блокирует:** —
**Оценка:** ~5 строк изменений, только `sprite.c`

## Что происходит

`sprite_render()` (`sprite.c`) обрезает верх спрайта по краю экрана:

```c
if (drawStartY < 0) {
    drawStartY = 0;
}
```

а выборку по текстуре начинает с нуля независимо от того, обрезал он
что-нибудь или нет:

```c
float stepY = (float)texH / (float)spriteHeight;
float texPos = 0.0f;
```

То есть кадр целиком укладывается в оставшиеся строки: чем ближе спрайт,
тем сильнее он сплющен по вертикали, хотя должен уходить за край экрана.
На расстоянии, где спрайт выше экрана, видно всю фигуру, сжатую в высоту,
вместо её верхней части.

По горизонтали той же ошибки нет: `texX` считается от неотсечённого
`spriteScreenX`, а не от обрезанного `drawStartX`.

## Как воспроизвести

Воспроизведение из `bug-009` с подходом вплотную: на глубине около 1.0
залитый кадр 64×64 меряется как 120×266 пикселей фреймбуфера — при верной
обрезке ширина и высота видимой части должны сохранять отношение кадра,
а не расходиться втрое.

## Что сделать

- [ ] Запомнить неотсечённый верх спрайта до присваивания `drawStartY = 0`
      и начинать выборку с него:
      ```c
      float texPos = (float)(drawStartY - spriteTopY) * stepY;
      ```

## Закрыто

2026-10-16 — исправлено, как в задаче: `sprite_render()` запоминает
неотсечённый верх в `spriteTopY` до обрезки `drawStartY` и начинает
выборку по текстуре со строки кадра, которая приходится на первую строку
экрана.

Дефект был не сплющиванием, а сдвигом. `stepY` и раньше считался от
полной `spriteHeight`, поэтому масштаб сохранялся, а неверным был только
отсчёт: верхняя строка кадра всегда рисовалась у верхнего края экрана.
Верх обрезается только ближе глубины `2 * scale - 1` (у импа это 0.44), и
там же пол уходит ниже экрана, так что низ обрезан всегда. Фигура при
подходе не уходила за верхний край, а сползала вниз, оставляя голову у
края. Отношение сторон видимой части при обрезке с нескольких сторон
масштаб не характеризует, поэтому мерили по узору, а не по залитому кадру.

Воспроизведение: открытая комната, игрок в `(20.5, 11.5)`, `E` в
`(18.5, 11.5)`, вместо `assets/players/marine/idle_64x64.png` кадр 64×64
из клеток 8×8 текселей, цвет каждой клетки кодирует её строку и столбец.
Игрок подходит вплотную, затем замер в пикселях фреймбуфера:

| Величина | До | После | Ожидание |
|---|---|---|---|
| клетка по вертикали × по горизонтали | 120 × 120 | 103 × 103 | равны |
| видимая часть верхней клетки | 120 из 120 | 52 из 103 | 52 (верх на −52 при глубине 0.35) |

Кадры без обрезки, в том числе кадр со стартовой позиции, совпадают с
прежними попиксельно.

# 07-05 — Клиент: отправка ввода, приём снапшотов

**Этап:** 7 — Сеть: транспорт, протокол, снапшоты
**Зависит от:** 07-04, 06-05
**Блокирует:** 07-06, 07-07, 08-01, 08-02, 08-04
**Оценка:** ~200 строк нового кода

## Контекст

Первая версия клиента — намеренно наивная: применяет присланное состояние
«как есть», без интерполяции и предсказания. Движение будет рывками на
20 Гц, а своё движение — с задержкой на RTT. Это чинится на этапе 8;
сначала нужно убедиться, что базовый обмен работает.

## Что сделать

- [ ] `src/net_client.h`:
  ```c
  typedef enum { CL_DISCONNECTED, CL_CONNECTING,
                 CL_CONNECTED, CL_REJECTED } ClientState;

  typedef struct Client Client;
  Client *client_create(void);
  int     client_connect(Client *c, const char *addr, uint16_t port);
  void    client_destroy(Client *c);
  void    client_send_input(Client *c, const PlayerInput *in);
  void    client_poll(Client *c);       /* раз в кадр */
  ClientState client_state(const Client *c);
  World  *client_world(Client *c);
  int     client_local_player(const Client *c);
  ```
- [ ] Handshake: `connect` → `MSG_JOIN` → ожидание `MSG_ACCEPT`
      (таймаут 5 с → `CL_REJECTED` с причиной)
- [ ] По `MSG_ACCEPT`: `world_load()` карты из пакета, запомнить `your_id`
      как `local_player`
- [ ] `MSG_SNAPSHOT` → `snapshot_decode()` → `snapshot_apply()` в
      локальный `World`; пакет, который `snapshot_decode()` не принял,
      отбрасывать. Снапшоты с `tick` старше уже применённого игнорировать
- [ ] Отправка `MSG_INPUT` каждый тик (60 Гц), unreliable
- [ ] События из снапшота складывать в `EventQueue` мира — их разберёт 07-06
- [ ] Рендер: `sprites_build_from_world()` (06-05) + существующий
      `raycast_render()` / `sprite_render()` / `hud_draw()`
- [ ] Обработка разрыва: `NET_EV_DISCONNECT` → `CL_DISCONNECTED`,
      выход в меню (экран сделает 09-04)

## Затрагиваемые файлы

`net_client.c/.h` (новые), `main.c`, `CMakeLists.txt`

## Критерий готовности

- [ ] Два процесса на локалхосте: оба игрока видят друг друга и движение
      друг друга
- [ ] Выстрел одного игрока по врагу отражается у второго (хп врага, труп)
- [ ] Подобранная одним игроком аптечка исчезает у обоих
- [ ] Дверь, открытая одним, открыта у второго
- [ ] Убийство сервера → клиент корректно выходит, не падает

## Замечания

Ожидаемые на этом этапе артефакты, которые **не** являются багами:
рывки чужих игроков (20 Гц без интерполяции) и задержка своего движения
на RTT. Если на локалхосте (RTT ≈ 0) своё движение уже ощущается плохо —
проблема не в сети, а в 06-06.

`snapshot_apply()` затирает и локального игрока тоже. Пока это так и
задумано; в 08-02/08-03 локальный игрок будет исключён из прямого
применения и пойдёт через реконсиляцию.

## Закрыто

2026-10-17 — клиент сетевой игры — `src/net_client.c/.h`. Запуск:
`doom-clone --connect <адрес> [--port N]`. Клиент подключается к серверу из
07-04 и раз в тик шлёт `MSG_INPUT`. Каждый снапшот новее уже применённого он
кладёт в свой `World` как есть и рисует этот мир тем же рендером, что и
одиночная игра. Модуль собирается только при `ENABLE_MULTIPLAYER`.

С «Что сделать» реализация расходится в следующем:

- **Флаги запуска.** В `main.c` разбираются только `--connect` и `--port`.
  Без клиента нечего проверять, а остальное (`--host`, `--dedicated`,
  `--name`, `--snaprate`, `GameSession`) остаётся за 07-07. Неизвестный
  аргумент выводит сообщение и `usage`. Код клиента в `main.c` стоит под
  `#ifdef ENABLE_MULTIPLAYER`: этот макрос задаёт `CMakeLists.txt`, и сборка
  `-DENABLE_MULTIPLAYER=OFF` на `--connect` отвечает, что сети в ней нет.
- **Сервер для проверки — `tests/net_serve.c`**, по решению пользователя.
  Это ручная утилита рядом с `net_echo`:
  `build/tests/net_serve [карта] [порт]` из корня проекта гоняет
  `net_server.c` на 60 Гц и печатает входы и выходы игроков. Ctrl+C
  отпускает клиентов сразу, `kill -9` оставляет их ждать таймаута. В ctest
  она не входит. Её заменит `--host --dedicated` из 07-07, там же она и
  удаляется.
- **API.** Добавлена `client_reason()` — причина конца соединения
  человеческими словами: сейчас она идёт в stderr, на экран её выведет
  09-04. В `net_transport.h` добавлена `net_time()`, часы ENet: по ним
  таймаут рукопожатия проверяется сдвигом часов (`enet_time_set()`), а не
  ожиданием. В `config.h` добавлена `NET_CONNECT_TIMEOUT_MS 5000`.
- **`CL_CONNECTED` наступает с первым снапшотом, а не с `MSG_ACCEPT`**:
  до снапшота в мире нет игрока, глазами которого смотреть. Таймаут 5 с
  отсчитывается от `client_connect()` до первого снапшота. Неудача до него
  даёт `CL_REJECTED`, после него — `CL_DISCONNECTED`.
- **Вводы нумерует клиент**, по порядку с нуля на каждое подключение;
  `tick` из `PlayerInput` не используется. `World.tick` из снапшота
  прыгает на три за раз, а сервер отбрасывает ввод не новее прошлого:
  с номером тика мира до сервера доходил бы один ввод из трёх.
- **События.** `client_poll()` очищает `World.events` и дописывает туда
  события всех снапшотов, применённых за этот вызов, — `snapshot_apply()`
  сам по себе оставил бы только последние. Проигрывает их 07-06. Звука в
  режиме клиента до неё нет.
- **Разрыв и отказ.** Причина печатается в stderr, игра уходит в меню, а
  Enter в меню подключает снова, новым игроком. Пауза сетевую игру не
  останавливает: `client_poll()` идёт каждый кадр, анимации тоже. Ввод
  уходит только в `GSTATE_PLAYING`.
- **Своя отдача в HUD не видна.** `Weapon.anim` в снапшот не входит, поэтому
  оружие в руках у клиента не дёргается при выстреле, хотя патроны
  тратятся. Это часть предсказания из 08-02, где локально проигрывается
  отдача.

Тест — `tests/test_net_client.c`, 30 случаев по настоящим сокетам на
127.0.0.1. Клиенты в нём работают против настоящего сервера и против
подставного, который говорит на протоколе вручную и шлёт то, чего настоящий
не шлёт: отказы, старые и битые снапшоты, `MSG_ACCEPT` с путём вместо имени
карты, молчание после `MSG_ACCEPT`. Карту из `MSG_ACCEPT` клиент ищет в
`assets/maps/` рабочего каталога, поэтому `tests/CMakeLists.txt` заводит этот
каталог рядом с тестом. Тест ловит все 16 ручных подстановок в
`net_client.c`. Все 125 исполняемых изменённых строк исполняются тестами. 10
прогонов `ctest -j8` подряд прошли без единого падения. В
`test_net_transport.c` добавлен тест `net_time()`.

Критерии проверены на Linux, сервером `net_serve` и двумя процессами
`doom-clone --connect 127.0.0.1` на разных Xvfb (`:100`, `:101`), по снимкам
экрана:

- каждый видит другого. Второй видит, как первый уходит по коридору и
  становится меньше;
- первый убил импа в конце коридора. У второго на этом месте лежит труп;
- первый открыл дверь (10,11) — у второго на месте двери проём. Сержант
  у этой двери, пока проверяющий разглядывает снимки, успевает убить обоих:
  сетевая игра идёт в реальном времени и не останавливается. Поэтому
  сержанта и второго импа заранее убил скриптовый клиент на том же
  `net_client.c`;
- подбор проверен на броне (9,15), а не на аптечке: аптечку подбирают
  только раненым, а механизм тот же — бит в `items_alive`. Броня
  исчезла у второго, у первого в HUD стало 50 брони;
- `kill -9` сервера: оба клиента живы и через 4,9 с в меню, в stderr
  `Disconnected from 127.0.0.1: the connection to the server is lost`.
  Enter без сервера — через 5,2 с `Cannot join … the server did not answer`
  и снова меню. После перезапуска сервера оба вошли снова. Ctrl+C на
  сервере — меню сразу. Esc из меню клиента — сервер сразу пишет, что
  игрок вышел.

Одиночная игра без флагов не открывает ни одного сокета `AF_INET`
(`strace -f -e trace=socket` показывает только `AF_UNIX` до X-сервера).
Сборка `-DENABLE_MULTIPLAYER=OFF` проходит: 14 тестов, ни одной сетевой цели.
